# Риск задержки и объяснения прогноза

`final_model.cbm` — регрессор поправки к `cur_dev_s`. Классификатор использует тот же фиксированный порядок 78 признаков и событие **`target_delay_s > 120`**. Входная телеметрия ограничена одновременно `event_time <= T` и `receive_time <= T`. Будущее плановое расписание допустимо; фактические будущие прибытия и ответы в признаки не входят.

## Запуск

Из корня репозитория запустить `python ml_service/research/vovchik/train_from_notebook.py`. Он выполняет кодовые ячейки `unified.ipynb` в том же порядке, что **Run All** в Jupyter. По умолчанию `RETRAIN_REGRESSOR = True`: регрессор и классификатор риска обучаются заново. Данные берутся из `dataset/`, результаты сохраняются в `ml_service/research/vovchik/results/`, полный конкурсный файл — в корневом `submission.csv` и `dataset/submission.csv`.

При `RETRAIN_REGRESSOR = False` notebook загружает регрессор из `results/final_model.cbm` и переобучает только риск. После проверки для запуска сервиса скопировать три файла моделей (`final_model.cbm`, `risk_model.cbm`, `risk_metadata.json`) из `results/` в `ml_service/app/artifacts/` и пересобрать Docker-образ ML-сервиса.

Зависимости: Python, numpy, pandas, catboost, scipy, scikit-learn и nbformat. Отдельный пакет `shap` не нужен.

## Обучение и проверка

Уникальные времена T в train делятся хронологически на 60% / 20% / 20%: обучение классификатора, обучение sigmoid-калибровки, выбор между исходной вероятностью и sigmoid по меньшему Brier. Точки, фактический ответ которых ещё недоступен к следующей границе, исключаются из предыдущей части. После выбора модель не переобучается на калибровочных данных. Классовые веса не используются.

Test не участвует в обучении или программном выборе калибровки. Однако тест смотрели при разработке; результат — диагностическая оценка, а не слепая финальная проверка. Train/test содержат те же даты и пересекающиеся ТС, хотя sample_id и целевые события train/test не пересекаются. Это не оценка переноса на следующий день или новые ТС; train также содержит синтетические ТС.

Текущие результаты на 353 test-точках, 86 положительных событиях:

| Показатель | Значение |
|---|---:|
| MAE регрессора | 63.8795 с |
| MAE базового прогноза `cur_dev_s` | 93.3598 с |
| ROC-AUC риска | 0.9146 |
| Average precision риска | 0.7840 |
| Brier исходных вероятностей | 0.0980 |
| Brier выбранных sigmoid-вероятностей | 0.0993 |
| ECE (10 интервалов), исходные / sigmoid | 0.0511 / 0.0648 |

На train выбран sigmoid, но **на test он немного хуже исходных вероятностей**. Это зафиксировано в отчёте; нельзя утверждать, что калибровка улучшила test или что проценты гарантированно точны. Для утверждения о качестве на новых днях нужен дополнительный независимый временной тест. Brier оценивает и калибровку, и различающую способность; отдельная таблица калибровки содержит фактическую частоту, среднюю вероятность и число примеров в каждом интервале.

## Контракт для frontend

Верхний уровень JSON: `schemaVersion` и `records`. Объединять записи с существующими данными интерфейса по `sampleId`. Разметка UI здесь не менялась.

Поля каждой записи:

- `sampleId` — ключ точки.
- `predictionSec` — прогноз задержки, совместим с существующим UI; `predicted_delay_s` — его идентичный алиас.
- `delayProbability` — вероятность от 0 до 1 события задержки **строго больше 120 с**, не вероятность любой положительной задержки.
- `delayThresholdSec` — 120; `probabilityMethod` — `raw` или `sigmoid`.
- `explanation.factors` — до трёх наибольших по модулю ненулевых SHAP-вкладов регрессора. Каждый содержит `feature`, русскую `label`, исходное значение `value` (null при пропуске) и `shapValueSec` со знаком. Если все вклады нулевые, список пуст.
- `explanation.currentDeviationSec` — текущая задержка, явно добавленная вне регрессора.
- `explanation.baseValueSec` — базовое значение SHAP для **поправки**.
- `explanation.remainingShapValueSec` — суммарный вклад не показанных признаков.

Проверяемое равенство без округления:

```text
predictionSec = currentDeviationSec + baseValueSec
              + sum(factor.shapValueSec) + remainingShapValueSec
```

Положительный SHAP увеличивает задержку, отрицательный уменьшает. Это объяснение регрессионного прогноза, не объяснение вероятности классификатора и не причинный диагноз. Низкая скорость/простой не доказывают пробку на перекрёстке или длительную посадку: отдельных подтверждающих данных нет. Значения округлять только для отображения.

## Использование в backend

```python
from ml_service.app.services.ml_risk import load_models, predict_for_frontend

regressor, risk_model, metadata = load_models("ml_service/app/artifacts", "ml_service/app/artifacts/final_model.cbm")
# feature_frame — результат существующего build_features, с sample_id и всеми 78 признаками.
# Для одного прогноза можно передать F_validate.iloc[[0]].
records = predict_for_frontend(regressor, risk_model, metadata, feature_frame)
```

Модели загружать один раз при старте сервиса. Входные колонки переставляются по сохранённому порядку; пропущенная колонка вызывает понятную ошибку. Для онлайн-инференса backend должен собрать ту же полную схему признаков, включая NaN для недоступных числовых значений. Сырые GPS-пакеты эта функция не принимает. Совместимость проверяется по структуре модели (деревья, признаки, категориальные статистики, масштаб и смещение); служебные метаданные CatBoost не влияют на проверку. Изменение самой модели требует пересоздания связанных артефактов. SHA-256 исходного файла также сохраняется для учёта версии.

Проверки: `python -m unittest discover -s ml_service/research/vovchik/tests -v`. Проверяются строгий порог, временные границы и purge, отсутствие влияния будущих/ещё не полученных пакетов, порядок признаков, SHAP-аддитивность, сохранение модели, формат submission.

Основания: [CatBoost SHAP](https://catboost.ai/docs/en/concepts/shap-values), [вероятностная калибровка scikit-learn](https://scikit-learn.org/1.7/modules/calibration.html).
