# Документация Metrohack

Материалы для пункта 4 сдачи: **Sphinx по Python-коду и OpenAPI/Swagger по API**.

## Открыть готовый справочник

Скачайте репозиторий и откройте `docs/site/index.html` в браузере. Сайт уже собран: Python и работающая модель для чтения не нужны. Внутри — архитектура, форматы данных, производные признаки, ограничения, справочник модулей и API.

Или из корня репозитория выполните:

```bash
docker compose -f compose.docs.yaml up -d
```

Откройте **http://localhost:8082**. Запускается только документация.

## API

| Сервис | Swagger после запуска системы | Сохранённая OpenAPI-схема |
|---|---|---|
| Backend | http://localhost:8000/docs | [backend.json](openapi/backend.json) |
| ML | http://localhost:8001/docs | [ml.json](openapi/ml.json) |

Инструкция запуска системы: [JURY_GUIDE.md](../JURY_GUIDE.md). В Swagger выберите `GET /health` → **Try it out** → **Execute**; ожидается `200` и `{"status":"ok"}`. Затем проверьте исторический режим на дашборде.

Статические страницы Swagger доступны из готового сайта, только для чтения; их оформление загружается из CDN и требует интернета. JSON-схемы и основной справочник доступны без сети. Адреса `localhost` работают на машине, где запущены контейнеры.

## Обновить документацию

Python 3.12+, отдельное окружение. Из корня репозитория:

```bash
python -m pip install -r docs/requirements.txt -r backend/requirements.txt -r ml_service/requirements.txt
python docs/build.py
```

Скрипт извлекает классы, функции, сигнатуры и поля из кода, экспортирует схемы из реальных FastAPI-приложений, проверяет Swagger и health через ASGI и собирает Sphinx с проверкой предупреждений. Он загружает существующие ML-артефакты, но не обучает модель и не запускает NDTP. Подробности — на странице «Сборка и публикация» готового сайта.
